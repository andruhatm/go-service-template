# Руководство по просмотру детальной страницы прогноза

## Обзор

Добавлена функциональность просмотра результатов прогноза на отдельной странице с интерактивным линейным графиком, отображающим:
- **Исторические данные** - данные метрики, на основе которых был создан прогноз
- **Спрогнозированные значения** - предсказанные значения на будущие периоды
- **Пороговое значение** (опционально) - если настроено

## Что было реализовано

### 1. Frontend компоненты

#### ForecastDetailComponent
- **Расположение**: `frontend/src/app/routed/anomaly/components/forecast-detail/`
- **Функциональность**:
  - Отображение подробной информации о прогнозе
  - Интерактивный линейный график с историческими и прогнозируемыми данными
  - Обработка различных статусов прогноза (pending, processing, completed, failed)
  - Адаптивный дизайн для различных размеров экрана

#### MetricsQueryService
- **Расположение**: `frontend/src/app/services/metrics-query.service.ts`
- **Функциональность**:
  - Запрос исторических данных из VictoriaMetrics
  - Запрос прогнозируемых данных с фильтрацией по forecast_id
  - Поддержка фильтрации по типу метрики (actual, forecast)
  - Преобразование данных VictoriaMetrics в формат для графиков

### 2. Backend изменения

#### Обновление MetricsQueryHandler
- **Файл**: `go-api/handlers/metrics_query_handler.go`
- **Изменения**:
  - Добавлена поддержка опциональных параметров `type` и `forecastId` в запросе
  - Построение PromQL запросов с учетом фильтров
  - Примеры запросов:
    - Исторические данные: `metric_name{name="object_name", type="actual"}`
    - Прогноз: `metric_name{name="object_name", type="forecast", forecast_id="uuid"}`

### 3. Роутинг

Добавлен новый маршрут в `anomaly-routing.module.ts`:
```typescript
{
  path: ':id',
  component: ForecastDetailComponent,
}
```

URL для доступа: `/anomaly/{forecast-id}`

### 4. UI улучшения

- Добавлена кнопка "Просмотр" (иконка visibility) в список прогнозов
- Обновлена таблица прогнозов для быстрого перехода к детальной странице

## Как использовать

### Просмотр прогноза

1. Перейдите на страницу "Прогнозирование" (`/anomaly`)
2. В списке прогнозов найдите нужный прогноз
3. Нажмите кнопку с иконкой глаза (visibility) в колонке "Действия"
4. Откроется детальная страница с информацией и графиком

### Детальная страница прогноза

На странице отображается:

#### Информационная карточка
- Метрика
- Объект мониторинга
- Статус прогноза
- Периоды и частота прогноза
- Шаг данных
- Режим сезонности
- Даты создания и прогноза
- Количество точек прогноза

#### График
- **Синяя линия** - исторические данные (actual)
- **Оранжевая линия** - прогнозируемые значения (forecast)
- Интерактивность: наведение курсора показывает точные значения
- Timeline: возможность навигации по временной шкале
- Автоматическое масштабирование

### Навигация
- Кнопка "Назад" в верхней части страницы для возврата к списку

## Технические детали

### Структура данных

#### Запрос исторических данных
```typescript
{
  metricName: "test1",
  objectName: "enb27738",
  startTime: 1672531200,  // Unix timestamp
  endTime: 1704067200,    // Unix timestamp
  step: 3600,             // в секундах
  type: "actual"          // опционально
}
```

#### Запрос данных прогноза
```typescript
{
  metricName: "test1",
  objectName: "enb27738",
  startTime: 1704067200,
  endTime: 1706745600,
  step: 3600,
  type: "forecast",
  forecastId: "uuid-of-forecast"
}
```

### Формат ответа VictoriaMetrics

```typescript
{
  status: "success",
  data: {
    resultType: "matrix",
    result: [{
      metric: { name: "enb27738", type: "forecast" },
      values: [[timestamp, "value"], ...]
    }]
  }
}
```

### Библиотека графиков

Используется **@swimlane/ngx-charts** для отображения линейных графиков:
- Поддержка временных рядов
- Интерактивность
- Адаптивный дизайн
- Встроенная поддержка легенды и осей

## Обработка ошибок

Компонент обрабатывает следующие сценарии:
- Прогноз не найден (404)
- Прогноз в статусе pending/processing (отображается сообщение)
- Прогноз завершился с ошибкой (отображается ошибка)
- Нет данных для отображения (пустой график)
- Ошибки загрузки данных из VictoriaMetrics

## Требования к данным

Для корректной работы графика необходимо:

1. **Forecast-service должен записывать данные в VictoriaMetrics** с метками:
   - `name` - имя объекта мониторинга
   - `type="forecast"` - тип данных
   - `forecast_id` - UUID прогноза

2. **Исторические данные должны иметь метку** `type="actual"` или отсутствие метки type

3. **Формат меток в VictoriaMetrics**:
```
metric_name{name="object_name", type="forecast", forecast_id="uuid"} value timestamp
metric_name{name="object_name", type="actual"} value timestamp
```

## Дальнейшие улучшения

Возможные расширения функциональности:

1. **Доверительные интервалы**: отображение yhat_lower и yhat_upper из Prophet
2. **Пороговые значения**: добавление горизонтальной линии порога
3. **Экспорт данных**: возможность скачать данные в CSV/Excel
4. **Зум и панорамирование**: расширенная интерактивность графика
5. **Множественные метрики**: сравнение нескольких прогнозов на одном графике
6. **Аннотации**: добавление меток важных событий на графике
7. **Кастомизация**: выбор цветов, типов линий, маркеров

## Известные ограничения

1. График отображает только завершенные прогнозы (status: completed)
2. Максимальное количество точек на графике ограничено производительностью браузера
3. Для больших временных диапазонов рекомендуется увеличить step
4. График работает только с числовыми метриками

## Отладка

### Проверка данных в VictoriaMetrics

```bash
# Проверить исторические данные
curl "http://victoriametrics:8428/api/v1/query_range?query=test1{name=\"enb27738\"}&start=1672531200&end=1704067200&step=3600"

# Проверить данные прогноза
curl "http://victoriametrics:8428/api/v1/query_range?query=test1{name=\"enb27738\",type=\"forecast\",forecast_id=\"uuid\"}&start=1704067200&end=1706745600&step=3600"
```

### Проверка через API

```bash
# Получить прогноз
curl -X GET "http://localhost:8080/api/forecasts/{forecast-id}" \
  -H "Authorization: Bearer {token}"

# Запросить метрики
curl -X POST "http://localhost:8080/api/metrics/query" \
  -H "Content-Type: application/json" \
  -d '{
    "metricName": "test1",
    "objectName": "enb27738",
    "startTime": 1672531200,
    "endTime": 1704067200,
    "step": 3600,
    "type": "forecast",
    "forecastId": "uuid"
  }'
```

## Поддержка

При возникновении проблем проверьте:
1. Статус forecast-service: `curl http://forecast-service:8082/health`
2. Доступность VictoriaMetrics: `curl http://victoriametrics:8428/health`
3. Логи Go API: `docker-compose logs go-api`
4. Логи forecast-service: `docker-compose logs forecast-service`
5. Консоль браузера для ошибок frontend
