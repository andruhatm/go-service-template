## 📐 Формулы для LaTeX (для PowerPoint Equation Editor)

### Аддитивная модель:
```latex
y(t) = T(t) + S(t) + E(t)
```

### Трендовая компонента:
```latex
T(t) = at + b
```
```latex
a = \frac{n\sum t_i y_i - \sum t_i \sum y_i}{n\sum t_i^2 - (\sum t_i)^2}
```

### Сезонная компонента:
```latex
S(h) = A \cdot \sin\left(\frac{2\pi(h-\phi)}{24}\right)
```

### WAPE (основная метрика):
```latex
\text{WAPE} = \frac{\sum_{i=1}^{n} |y_i - \hat{y}_i|}{\sum_{i=1}^{n} |y_i|} \times 100\%
```

## ❓ Типичные вопросы комиссии и ответы

### 1. Почему выбран алгоритм Prophet?
**Краткий ответ (30 сек):**
"Prophet выбран как baseline модель по трем причинам: первое — простота интерпретации через явную декомпозицию на тренд и сезонность; второе — высокая скорость обучения и прогнозирования, 0,111 секунды на прогноз; третье — низкие требования к объему данных, достаточно 30 дней для обучения. Для более сложных паттернов, таких как недельная сезонность, запланирована интеграция SARIMA."

### 2. Как система обрабатывает аномалии?
**Краткий ответ (30 сек):**
"Двухэтапный подход: Prophet автоматически исключает выбросы через механизм changepoints, а остаточная компонента E(t) анализируется для выявления аномалий, превышающих 3 сигма от среднего. Экспериментально подтверждена робастность на метрике с 5% аномалий — WAPE составил 4,92%, что соответствует отличному качеству."

### 3. Масштабируемость для крупного оператора?
**Краткий ответ (30 сек):**
"Архитектура поддерживает горизонтальное масштабирование. VictoriaMetrics в кластерном режиме обрабатывает до 10 миллионов точек в секунду. Микросервис прогнозирования может быть реплицирован. Для оператора с 50 тысяч базовых станций и 100 метрик на каждую — это 5 миллионов метрик — система с 50 параллельными экземплярами сгенерирует все прогнозы примерно за 2 часа."

### 4. Как интегрироваться с существующей инфраструктурой?
**Краткий ответ (20 сек):**
"Система поддерживает стандартные протоколы: Prometheus exposition format для push/pull метрик, REST API с OpenAPI спецификацией для внешних систем, интеграция через SNMP и Node exporters."

### 5. Планы дальнейшего развития?
**Краткий ответ (30 сек):**
"Четыре приоритетных направления: первое — расширение модели для поддержки недельной сезонности; второе — автоматическое обнаружение аномалий с генерацией уведомлений; третье — ансамблевые методы для повышения точности; четвертое — модуль генерации периодических отчетов."
