# Механизм предотвращения дублирования метрик

## Проблема

При повторном импорте одного и того же файла с метриками по расписанию, существует риск дублирования данных в VictoriaMetrics. Например, если файл с метриками не изменился, но импорт происходит каждые 30 секунд, это может привести к:
- Избыточной записи одних и тех же данных
- Увеличению нагрузки на VictoriaMetrics
- Излишнему использованию ресурсов

## Решение

Реализованы **два механизма** защиты от дублирования:

### 1. Проверка хеша содержимого файла (SHA256)

**Как работает:**
- При каждом импорте вычисляется SHA256 хеш содержимого файла
- Хеш сравнивается с последним импортированным хешем из БД
- Если хеши совпадают → файл не изменился → импорт пропускается
- Если хеши различаются → файл изменился → выполняется импорт

**Преимущества:**
- ✅ Работает для всех типов источников (File, FTP, SFTP, HTTP)
- ✅ Детектирует любые изменения в содержимом
- ✅ Не зависит от времени модификации файла

**Пример:**
```go
// Вычисление хеша
fileHash := sha256(fileContent)
// "a3f5d8e2..." - хеш текущего файла

// Сравнение с последним хешем
if source.LastFileHash == fileHash {
    log.Info("File unchanged, skipping import")
    return // Импорт не выполняется
}
```

### 2. Проверка времени модификации (для локальных файлов)

**Как работает:**
- Для локальных файлов проверяется время последней модификации (mtime)
- Время сравнивается с сохраненным в БД
- Если файл не был изменен с момента последнего импорта → импорт пропускается

**Преимущества:**
- ✅ Быстрая проверка (не требует чтения всего файла)
- ✅ Работает на уровне файловой системы
- ✅ Дополнительная защита для File источников

**Пример:**
```go
fileInfo, _ := os.Stat(filePath)
currentModTime := fileInfo.ModTime()

if !currentModTime.After(source.LastFileModTime) {
    log.Info("File not modified, skipping import")
    return // Импорт не выполняется
}
```

## Схема базы данных

Добавлены два новых поля в таблицу `metric_sources`:

```sql
ALTER TABLE metric_sources 
ADD COLUMN last_file_hash VARCHAR(64),        -- SHA256 хеш последнего файла
ADD COLUMN last_file_mod_time TIMESTAMP;     -- Время модификации файла
```

## Алгоритм работы

```
1. Получить источник из БД
2. Скачать/прочитать файл с метриками
3. Вычислить SHA256 хеш содержимого
4. 
   ┌─────────────────────────────────────┐
   │ Проверка 1: Хеш содержимого         │
   └─────────────────────────────────────┘
   Если last_file_hash == current_hash:
     → Файл не изменился
     → Пропустить импорт
     → Обновить last_sync_at
     → Завершить

5. 
   ┌─────────────────────────────────────┐
   │ Проверка 2: Время модификации       │
   │ (только для локальных файлов)       │
   └─────────────────────────────────────┘
   Если file_mod_time <= last_file_mod_time:
     → Файл не был изменен
     → Пропустить импорт
     → Завершить

6. Файл изменился → Выполнить импорт
7. Записать метрики в VictoriaMetrics
8. Обновить в БД:
   - last_file_hash = current_hash
   - last_file_mod_time = file_mod_time
   - last_sync_at = now()
   - last_sync_status = 'success'
```

## Проверка работы

### 1. Создайте тестовый источник

```bash
# Создайте файл
cat > /tmp/test_metrics.txt << 'EOF'

# Добавьте источник через API или SQL
curl -X POST http://localhost:8081/api/ems \
  -H "Authorization: Bearer $TOKEN" \
  -d '{
    "source_name": "Dedup Test",
    "connection_type": "file",
    "host": "localhost",
    "FTPport": 0,
    "file_path": "/tmp/test_metrics.txt",
    "schedule": "30s",
    "enabled": true
  }'
```

### 2. Подождите первого импорта (30 сек)

```bash
# Проверьте логи
docker-compose logs -f go-api | grep "Dedup Test"

```

### 3. Проверьте, что повторный импорт пропускается

Через 30 секунд должно появиться:


## Особенности для разных типов источников

### File (локальные файлы)
✅ Проверка хеша содержимого  
✅ Проверка времени модификации  
→ **Двойная защита от дублирования**

### FTP
✅ Проверка хеша содержимого  
❌ Проверка времени модификации (не всегда доступно)  
→ **Защита на основе хеша**

### SFTP
✅ Проверка хеша содержимого  
⚠️ Проверка времени модификации (можно добавить)  
→ **Защита на основе хеша**

### HTTP
✅ Проверка хеша содержимого  
⚠️ Проверка ETag/Last-Modified (можно добавить)  
→ **Защита на основе хеша**

## Производительность

### Влияние на производительность

| Операция | Overhead | Комментарий |
|----------|----------|-------------|
| Вычисление SHA256 | ~1-5ms для файла 1MB | Незначительно |
| Проверка хеша в БД | <1ms | Индексированный запрос |
| Чтение mtime | <1ms | Системный вызов |
| **Итого** | **~2-10ms** | Минимальное влияние |

### Экономия ресурсов

При пропуске импорта экономится:
- ✅ Сетевая нагрузка на VictoriaMetrics
- ✅ Дисковое I/O для записи данных
- ✅ CPU для обработки метрик
- ✅ Память для буферизации

**Пример:** Если файл не изменяется 1 час, а импорт каждые 30 секунд:
- Без защиты: 120 импортов одних и тех же данных
- С защитой: 1 импорт + 119 пропущенных проверок

## Поведение при изменении расписания

Если вы измените частоту сбора:
```sql
UPDATE metric_sources 
SET schedule = '5m' 
WHERE id = 1;
```

Защита от дублирования продолжит работать:
- Первый импорт по новому расписанию → выполнится (если файл изменился)
- Последующие импорты → пропускаются (если файл не изменился)

## Ручной сброс состояния

Если нужно принудительно выполнить импорт (например, для тестирования):

```sql
-- Сбросить хеш и время модификации
UPDATE metric_sources 
SET last_file_hash = NULL,
    last_file_mod_time = NULL
WHERE id = 1;

-- Следующий импорт будет выполнен независимо от содержимого файла
```

## Мониторинг

### Метрики для отслеживания

Рекомендуется отслеживать:
1. **Количество пропущенных импортов** - показывает эффективность защиты
2. **Количество успешных импортов** - показывает реальные изменения
3. **Соотношение пропущенных/выполненных** - индикатор стабильности данных

### Запрос для статистики

```sql
SELECT 
    source_name,
    COUNT(CASE WHEN last_sync_status = 'success' THEN 1 END) as success_count,
    last_file_hash,
    EXTRACT(EPOCH FROM (NOW() - last_file_mod_time))/3600 as hours_since_change
FROM metric_sources
WHERE enabled = true
GROUP BY source_name, last_file_hash, last_file_mod_time
ORDER BY source_name;
```

## Преимущества решения

### ✅ Надежность
- Двойная проверка (хеш + mtime) для локальных файлов
- Работает для всех типов источников
- Не влияет на существующую функциональность

### ✅ Производительность
- Минимальный overhead (~2-10ms)
- Экономия ресурсов VictoriaMetrics
- Снижение сетевой нагрузки

### ✅ Прозрачность
- Подробное логирование
- Видимость в базе данных
- Легко мониторить и отлаживать

### ✅ Гибкость
- Можно отключить (сбросив хеш)
- Работает автоматически
- Не требует настройки
