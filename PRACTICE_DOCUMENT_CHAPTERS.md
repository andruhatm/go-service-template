## РЕФЕРАТ

**Программа:** Автоматизированная система мониторинга и прогнозирования показателей функционирования станций сотовой связи

### Аннотация

Автоматизированная система предназначена для операторов телекоммуникационных сетей для непрерывного мониторинга ключевых показателей производительности сетевого оборудования, анализа временных рядов телеметрических данных и прогнозирования поведения метрик качества обслуживания.

Разработанная автоматизированная система представляет собой взаимосвязь таких элементов, как математическая модель прогнозирования временных рядов на основе алгоритма Prophet, база данных реляционного типа PostgreSQL для хранения структурированных данных (объекты мониторинга, справочник метрик, конфигурации панелей управления, прогнозы, уведомления), специализированная база данных временных рядов VictoriaMetrics для хранения телеметрических данных с высокой степенью сжатия, база данных учетных записей пользователей в системе управления идентификацией Keycloak, серверный модуль RESTful API на языке Go для обработки запросов и координации компонентов, микросервис прогнозирования на языке Python с веб-фреймворком FastAPI, модуль веб-интерфейса на фреймворке Angular для визуализации данных и взаимодействия с пользователем.

Программный комплекс позволяет выполнять мониторинг в реальном времени метрик производительности базовых станций сотовой связи и узлов сетевой инфраструктуры, визуализировать временные ряды телеметрических данных на интерактивных графиках с настраиваемыми временными диапазонами, создавать персонализируемые панели управления с виджетами графиков для различных метрик, генерировать прогнозы значений метрик на заданный горизонт времени (от нескольких часов до нескольких недель) с использованием алгоритмов машинного обучения, управлять справочником метрик конфигурации с описаниями, единицами измерения и пороговыми значениями, создавать и отслеживать уведомления о событиях в системе мониторинга, экспортировать данные временных рядов для последующего анализа, а также управлять учетными записями пользователей с разграничением прав доступа на основе ролевой модели (администратор, оператор мониторинга, наблюдатель).

Использование программного комплекса позволяет повысить эффективность эксплуатации телекоммуникационной инфраструктуры через проактивное управление ресурсами на основе прогнозирования нагрузки, снизить время реакции на возникающие проблемы качества обслуживания за счет централизованного мониторинга и системы уведомлений, оптимизировать планирование развития сети на основе анализа трендов ключевых показателей производительности, а также обеспечить соответствие требованиям стандартов качества обслуживания абонентов (QoS).

**Среды разработки:** GoLand 2024, PyCharm 2024, Visual Studio Code

## Обеспечение защиты информации

Программный комплекс предназначен для предприятий телекоммуникационной отрасли, для мониторинга и анализа ключевых показателей производительности сетевого оборудования с возможностью прогнозирования временных рядов телеметрических данных. Разработанный программный комплекс представляет собой взаимосвязь таких элементов, как математическая модель прогнозирования временных рядов на основе алгоритма Prophet, база данных PostgreSQL для хранения структурированных данных (объекты мониторинга, справочник метрик, конфигурации панелей управления, прогнозы, уведомления), база данных временных рядов VictoriaMetrics для хранения телеметрических данных, база данных учетных записей пользователей в системе Keycloak, серверное API на языке Go для обработки запросов и координации работы компонентов, микросервис прогнозирования на языке Python с веб-фреймворком FastAPI, клиентское веб-приложение на Angular для визуализации данных и взаимодействия с пользователем.

В программном комплексе предусмотрен механизм авторизации на основе ролевой политики через специализированную систему управления идентификацией и доступом Keycloak версии 22.0, реализующую современные стандарты аутентификации OpenID Connect 1.0 и OAuth 2.0, в связи с чем необходимо хранить данные учетных записей пользователей. В целях обеспечения безопасности пароли пользователей хранятся в виде хеш-значений с использованием криптографической соли, для генерации которых система Keycloak использует алгоритм bcrypt с адаптивной вычислительной сложностью, что обеспечивает высокую устойчивость к атакам подбора паролей методом грубой силы. Алгоритм bcrypt превосходит устаревший MD5 по уровню криптографической стойкости, поскольку MD5 является быстрым хеш-алгоритмом, подверженным коллизиям, в то время как bcrypt специально спроектирован для медленного вычисления хеша с возможностью настройки вычислительной сложности через параметр cost factor.

Разработанный программный комплекс рассчитан на работу трех типов пользователей – администратора, оператора мониторинга и наблюдателя, права которых программно разграничены таким образом, что каждый пользователь имеет доступ лишь к тем частям системы, к которым должен в соответствии со своими функциональными обязанностями. Оператор мониторинга имеет доступ к функциональности создания объектов мониторинга, настройки персональных панелей управления, генерации прогнозов и управления уведомлениями, но не может изменять справочные данные или управлять учетными записями пользователей. Наблюдатель имеет доступ только для чтения данных мониторинга, просмотра панелей управления, результатов прогнозирования и уведомлений без возможности их модификации.

### Архитектура аутентификации и авторизации

Аутентификация пользователей реализована на основе концепции Single Sign-On (SSO) через систему Keycloak с использованием протоколов OpenID Connect 1.0 и OAuth 2.0. После успешной аутентификации пользователь получает JWT (JSON Web Token) токен доступа, содержащий криптографически подписанную информацию об идентификаторе пользователя, времени истечения сессии и назначенных ролях. Клиентское веб-приложение на Angular автоматически добавляет токен доступа во все запросы к серверному API через заголовок Authorization в формате Bearer.

Серверное API, реализованное на языке Go, выполняет валидацию токенов через middleware-компонент, который проверяет криптографическую подпись токена с использованием публичного ключа сервера Keycloak, полученного через протокол OpenID Connect Discovery, проверяет временные метки токена для предотвращения использования устаревших токенов, извлекает информацию о ролях пользователя и добавляет ее в контекст запроса для последующей проверки прав доступа. На уровне обработчиков API endpoint-ов реализована детализированная проверка наличия необходимых ролей для выполнения запрашиваемой операции.

### Защита данных при передаче и хранении

В промышленной среде эксплуатации весь сетевой трафик между компонентами системы защищается с использованием протокола TLS (Transport Layer Security) версии 1.2 или выше, что предотвращает перехват конфиденциальных данных, включая токены аутентификации и телеметрические метрики. Серверное API настроено для обработки HTTPS-запросов с использованием современных криптографических наборов с поддержкой прямой секретности.

Взаимодействие между микросервисами внутри контейнерной среды Docker осуществляется через изолированные виртуальные сети, настроенные в конфигурации Docker Compose. Каждый сервис имеет доступ только к необходимым для его функционирования компонентам, что реализует принцип минимальных привилегий на сетевом уровне.

Реляционная база данных PostgreSQL хранит структурированные данные с обеспечением полной поддержки стандарта ACID для транзакций. База данных временных рядов VictoriaMetrics сохраняет телеметрические данные в оптимизированном сжатом формате. Для production-сред рекомендуется использование зашифрованных томов хранения с управлением ключами шифрования через специализированные сервисы. Резервные копии данных хранятся в зашифрованном виде с ограничением доступа минимальным кругом администраторов.

### Защита от веб-уязвимостей

Система защищена от основных классов веб-уязвимостей согласно классификации OWASP Top 10:

**Injection-атаки.** Все взаимодействие с базой данных PostgreSQL осуществляется через параметризованные запросы (prepared statements) с использованием драйвера lib/pq для Go, что исключает возможность SQL-инъекций. На уровне бизнес-логики выполняется валидация всех входных данных с проверкой типов, форматов и диапазонов значений.

**Cross-Site Scripting (XSS).** Фреймворк Angular автоматически выполняет санитизацию всех данных перед отображением в DOM, экранируя HTML-теги и JavaScript-код. Content Security Policy (CSP) заголовки ограничивают источники загрузки ресурсов только доверенными доменами.

**Cross-Site Request Forgery (CSRF).** Использование токен-based аутентификации через JWT вместо cookie-based sessions снижает вероятность CSRF-атак. Политика CORS на серверном API разрешает запросы только от доверенных источников.

**Broken Authentication.** Функциональность аутентификации делегирована системе Keycloak, которая реализует защиту от атак грубой силы через временную блокировку учетных записей после нескольких неудачных попыток входа, требования к сложности паролей, безопасное хранение паролей в хешированном виде с использованием алгоритма bcrypt.

**Sensitive Data Exposure.** Конфиденциальные данные конфигурации (пароли баз данных, секретные ключи) хранятся в отдельных файлах конфигурации или переменных окружения, которые не включаются в систему контроля версий Git.

### Изоляция компонентов

Функциональность системы распределена между независимыми микросервисами, каждый из которых выполняется в изолированном Docker-контейнере. Изоляция обеспечивается через механизмы ядра Linux (namespaces и cgroups), предотвращая несанкционированный доступ между компонентами. Каждый контейнер имеет собственную файловую систему и доступ только к необходимым для его функционирования сервисам. Порты сервисов не экспонируются на хост-системе, за исключением точек входа, что минимизирует поверхность атаки. Для критических компонентов используются отдельные тома для персистентного хранения данных с минимально необходимыми правами доступа.

### Аудит и логирование

Все компоненты системы генерируют структурированные логи событий, включающие информацию о попытках аутентификации, операциях модификации данных и ошибках доступа. Keycloak обеспечивает детальный аудит событий аутентификации с информацией об IP-адресе, времени и идентификаторе пользователя. Серверное API логирует все входящие запросы с информацией о пользователе и выполненной операции. Централизованный сбор логов может быть реализован через интеграцию с ELK-стеком или альтернативными решениями.

### Дополнительные меры безопасности

Для повышения уровня защиты при развертывании в промышленных условиях рекомендуется:

1. Многофакторная аутентификация для пользователей с административными привилегиями через интеграцию Keycloak с TOTP или аппаратными токенами.

2. Web Application Firewall для фильтрации вредоносных HTTP-запросов на основе сигнатур известных атак.

3. Регулярные сканирования безопасности контейнерных образов для выявления известных уязвимостей в зависимостях.

4. Сегментация сети с разделением компонентов по зонам безопасности и настройкой межсетевых экранов.

5. Intrusion Detection System для мониторинга сетевого трафика и обнаружения аномалий в реальном времени.

Реализованная система защиты информации обеспечивает баланс между безопасностью и удобством использования, соответствует современным стандартам разработки защищенных веб-приложений.

## Выводы и итоги практики

В ходе преддипломной практики был разработан полнофункциональный программный комплекс мониторинга и анализа телекоммуникационных метрик, реализующий современную микросервисную архитектуру с применением передовых технологий разработки программного обеспечения. Комплекс представляет собой распределенную систему, состоящую из веб-интерфейса на Angular, серверного API на Go, микросервиса прогнозирования на Python, специализированных баз данных PostgreSQL и VictoriaMetrics, а также системы управления идентификацией Keycloak.

### Выполненные этапы разработки

**Проектирование архитектуры системы.** На начальном этапе была спроектирована многоуровневая архитектура программного комплекса с четким разделением ответственности между компонентами. Выбор микросервисной архитектуры обоснован требованиями к масштабируемости, независимому развертыванию компонентов и возможностью использования различных технологических стеков для разных модулей в соответствии со спецификой решаемых задач. Определены интерфейсы взаимодействия между компонентами, формат обмена данными и протоколы коммуникации.

**Разработка серверного API и бизнес-логики.** Реализован RESTful API на языке Go версии 1.24, обеспечивающий обработку запросов от клиентского веб-приложения и координацию работы всех компонентов системы. Серверное API включает модули управления объектами мониторинга, справочником метрик конфигурации, панелями управления, прогнозами временных рядов и системой уведомлений. Разработана система миграций базы данных для управления эволюцией схемы данных. Реализована интеграция с PostgreSQL для хранения структурированных данных и VictoriaMetrics для работы с временными рядами телеметрических метрик.

**Реализация системы аутентификации и авторизации.** Интегрирована система управления идентификацией Keycloak с реализацией Single Sign-On на основе протоколов OpenID Connect и OAuth 2.0. Разработана ролевая модель управления доступом с тремя уровнями прав: администратор, оператор и наблюдатель. Реализован механизм валидации JWT-токенов на серверном API и автоматического обновления токенов на клиентском приложении. Создан централизованный сервис аутентификации KeycloakAuthService, решающий проблемы с таймингом при ленивой загрузке модулей Angular.

**Разработка клиентского веб-приложения.** Реализовано одностраничное веб-приложение на фреймворке Angular версии 18.0 с использованием TypeScript 5.4 и библиотеки компонентов Angular Material. Приложение включает модули для управления объектами мониторинга, визуализации метрик на интерактивных графиках, создания и настройки персонализируемых панелей управления с виджетами, просмотра и управления прогнозами, работы с системой уведомлений. Реализована адаптивная верстка, обеспечивающая корректное отображение интерфейса на различных размерах экранов.

**Создание модуля прогнозирования временных рядов.** Разработан отдельный микросервис на Python версии 3.11 с использованием веб-фреймворка FastAPI и библиотеки прогнозирования Prophet. Сервис обеспечивает извлечение исторических данных из VictoriaMetrics, обучение модели прогнозирования, генерацию прогнозов на заданный горизонт времени и запись результатов обратно в VictoriaMetrics с соответствующими метками. Реализована валидация входных данных через Pydantic модели и автоматическая генерация документации API в формате OpenAPI.

**Реализация системы панелей управления (Dashboards).** Создан модуль настраиваемых панелей управления, позволяющий пользователям создавать персонализированные представления данных мониторинга через добавление, изменение размеров и перемещение виджетов с графиками метрик. Реализована функциональность сохранения конфигурации панелей в базе данных, разделения панелей на персональные и общие, клонирования существующих панелей. Интегрирована библиотека angular-gridster2 для реализации drag-and-drop интерфейса размещения виджетов.

**Разработка системы уведомлений.** Реализован полнофункциональный модуль уведомлений, включающий серверный API для создания, чтения, обновления и удаления уведомлений, клиентский интерфейс с индикатором непрочитанных уведомлений и диалоговым окном для просмотра списка уведомлений. Система поддерживает различные типы уведомлений (информационные, предупреждения, критические), отслеживание статуса прочтения, фильтрацию по типу и сортировку по дате. Реализована возможность массовой пометки уведомлений как прочитанных.

**Экспериментальное исследование модуля прогнозирования.** Проведено детальное тестирование системы прогнозирования на девяти различных типах временных рядов, включающих простые детерминированные паттерны, метрики с сезонностью, временные ряды с высоким уровнем шума и случайными аномалиями, а также комбинированные реалистичные паттерны. Экспериментально подтверждена высокая точность прогнозирования со средним значением MAPE = 5.14%, что значительно превосходит целевые показатели (MAPE < 15%). Продемонстрирована высокая производительность системы со средним временем генерации прогноза 0.111 секунды, что обеспечивает возможность интерактивной работы и массового прогнозирования тысяч метрик.

**Контейнеризация и автоматизация развертывания.** Все компоненты системы упакованы в Docker-контейнеры с использованием многоступенчатой сборки для минимизации размера образов. Создана конфигурация Docker Compose для оркестрации всех сервисов с настройкой сетей, томов персистентного хранения данных и зависимостей между компонентами. Разработаны скрипты автоматизации для инициализации тестовых данных, настройки Keycloak и выполнения миграций базы данных.

**Обеспечение защиты информации.** Реализована многоуровневая система защиты, включающая аутентификацию через Keycloak с поддержкой Single Sign-On, ролевую модель управления доступом RBAC, валидацию JWT-токенов на серверном API, защиту от основных классов веб-уязвимостей (SQL Injection, XSS, CSRF), изоляцию компонентов на уровне контейнеров, логирование событий безопасности. Система соответствует современным стандартам разработки защищенных веб-приложений.

**Документирование системы.** Создана подробная техническая документация, включающая описание архитектуры системы, руководства по развертыванию и настройке компонентов, API документация для серверных endpoint-ов, инструкции по использованию клиентского интерфейса, результаты экспериментального исследования модуля прогнозирования. Документация обеспечивает воспроизводимость развертывания системы и упрощает дальнейшую разработку и поддержку.

### Задачи дальнейшей разработки

**Реализация механизма обнаружения аномалий в реальном времени.** Разработка алгоритмов автоматического обнаружения аномальных значений метрик на основе отклонения фактических значений от прогнозных, с настраиваемыми порогами чувствительности и автоматической генерацией уведомлений при обнаружении аномалий. Интеграция с системой уведомлений для оперативного информирования операторов о выявленных проблемах.

**Оптимизация производительности запросов к временным рядам.** Исследование возможностей кэширования результатов часто запрашиваемых временных интервалов, реализация агрегирования данных с переменной детализацией в зависимости от запрашиваемого временного диапазона, оптимизация запросов PromQL для снижения нагрузки на VictoriaMetrics при одновременной работе множества пользователей.

**Расширение возможностей визуализации данных.** Добавление новых типов графиков и диаграмм для визуализации различных видов метрик, включая heat maps для отображения интенсивности событий, sankey diagrams для визуализации потоков данных, географические карты для отображения метрик с привязкой к местоположению оборудования. Реализация функциональности экспорта графиков в форматы изображений для включения в отчеты.

**Разработка модуля генерации отчетов.** Создание системы автоматической генерации периодических отчетов с настраиваемым содержанием и периодичностью, включающих аналитику по ключевым показателям производительности, тренды метрик за заданный период, выявленные аномалии и их влияние на качество обслуживания. Поддержка экспорта отчетов в форматы PDF и Excel для интеграции с корпоративными системами управления.

**Интеграция с внешними системами управления сетью.** Разработка адаптеров для интеграции с системами управления телекоммуникационным оборудованием различных производителей для автоматического обнаружения объектов мониторинга, импорта метрик конфигурации и экспорта результатов анализа. Реализация поддержки стандартизованных протоколов обмена данными NETCONF, SNMP, OpenConfig.

**Реализация системы корреляции событий.** Разработка алгоритмов автоматического выявления корреляций между метриками различных объектов мониторинга для обнаружения взаимосвязей и причинно-следственных зависимостей в телекоммуникационной сети. Визуализация графа зависимостей метрик для упрощения диагностики сложных проблем.

**Улучшение модуля прогнозирования.** Исследование альтернативных моделей прогнозирования временных рядов, таких как ARIMA, LSTM нейронные сети, XGBoost, для сравнения точности и производительности с текущей реализацией на основе Prophet. Реализация ансамблевых методов, комбинирующих предсказания нескольких моделей для повышения точности. Разработка механизма автоматического подбора гиперпараметров моделей на основе характеристик конкретной метрики.

**Реализация механизма управления инцидентами.** Создание модуля для регистрации, отслеживания и управления инцидентами в телекоммуникационной сети, интегрированного с системой обнаружения аномалий и уведомлений. Поддержка workflow для эскалации инцидентов, назначения ответственных, отслеживания времени разрешения и анализа повторяющихся проблем.

**Разработка мобильного приложения.** Создание нативного мобильного приложения для iOS и Android или прогрессивного веб-приложения (PWA) для обеспечения доступа к ключевым функциям системы мониторинга с мобильных устройств. Реализация push-уведомлений для оперативного информирования операторов о критических событиях независимо от того, открыто ли веб-приложение в браузере.

**Оптимизация потребления ресурсов и масштабируемость.** Профилирование производительности всех компонентов системы для выявления узких мест, оптимизация запросов к базам данных, реализация эффективных алгоритмов кэширования. Исследование возможностей горизонтального масштабирования критических компонентов через репликацию и load balancing. Миграция на оркестрацию контейнеров Kubernetes для автоматического масштабирования в зависимости от нагрузки.

**Усиление системы защиты информации.** Реализация многофакторной аутентификации для пользователей с административными привилегиями, интеграция с Web Application Firewall для защиты от распространенных атак, внедрение системы мониторинга безопасности и автоматического реагирования на инциденты. Регулярные аудиты безопасности и тестирование на проникновение для выявления потенциальных уязвимостей.

### Перспективы развития программного комплекса

Разработанный программный комплекс обладает значительным потенциалом для расширения функциональности и применения в различных областях телекоммуникаций и смежных отраслей:

**Расширение на другие домены мониторинга.** Архитектура системы является достаточно гибкой для адаптации к мониторингу не только телекоммуникационной инфраструктуры, но и других распределенных систем, таких как центры обработки данных, облачные инфраструктуры, промышленные IoT-системы. Универсальность подхода к работе с временными рядами метрик позволяет применять систему для мониторинга любых физических или виртуальных объектов, генерирующих телеметрические данные.

**Интеграция с технологиями искусственного интеллекта.** Накопление больших объемов исторических данных о состоянии телекоммуникационной сети создает предпосылки для применения методов машинного обучения для решения более сложных задач, таких как долгосрочное прогнозирование емкости сети, автоматическая оптимизация конфигурации оборудования на основе паттернов использования, предиктивное обслуживание оборудования с прогнозированием вероятности отказов.

**Создание экосистемы плагинов и расширений.** Разработка архитектуры плагинов позволит сторонним разработчикам создавать дополнительные модули визуализации, аналитики и интеграции с внешними системами без модификации ядра программного комплекса. Это может способствовать формированию сообщества пользователей и разработчиков вокруг системы, ускоряя ее развитие и адаптацию к специфическим потребностям различных организаций.

**Коммерциализация и SaaS-модель.** Система может быть адаптирована для предоставления в виде облачного сервиса (Software as a Service), что упростит ее внедрение для небольших телекоммуникационных операторов без необходимости развертывания и поддержки собственной инфраструктуры. Мультитенантная архитектура обеспечит изоляцию данных различных организаций при совместном использовании вычислительных ресурсов.

**Стандартизация и вклад в open-source сообщество.** Публикация компонентов системы как проектов с открытым исходным кодом может способствовать их широкому распространению и получению обратной связи от сообщества разработчиков. Активное участие в разработке открытых стандартов обмена телеметрическими данными, таких как OpenMetrics и OpenTelemetry, обеспечит совместимость системы с широким спектром источников данных и инструментов анализа.

### Заключение

В результате преддипломной практики реализован современный программный комплекс мониторинга и анализа телекоммуникационных метрик, демонстрирующий применение передовых технологий и архитектурных подходов к решению задач управления качеством обслуживания в телекоммуникационных сетях. Система готова к применению в промышленных условиях после проведения дополнительного тестирования в реальной инфраструктуре и реализации рекомендаций по усилению защиты информации.

Экспериментальное исследование модуля прогнозирования подтвердило высокую точность и производительность реализованных алгоритмов, значительно превосходящие целевые показатели. Средняя относительная ошибка прогноза MAPE = 5.14% и среднее время генерации прогноза 0.111 секунды обеспечивают практическую применимость системы для интерактивного анализа данных и автоматизированного прогнозирования тысяч метрик телекоммуникационной сети.

Разработанная система обладает значительным потенциалом для дальнейшего развития и расширения функциональности, включая реализацию обнаружения аномалий, генерации отчетов, интеграции с внешними системами управления сетью, применения передовых методов машинного обучения для решения более сложных задач анализа и оптимизации. Архитектура комплекса обеспечивает гибкость для адаптации к изменяющимся требованиям и масштабирования для обработки растущих объемов данных.

Полученные в ходе практики практические навыки проектирования микросервисных архитектур, разработки распределенных систем, применения современных фреймворков и библиотек, обеспечения защиты информации и проведения экспериментальных исследований создают прочную основу для дальнейшей профессиональной деятельности в области разработки сложных программных систем для телекоммуникационной отрасли и смежных областей.
